# Real camera geometry model

The browser camera map is now backed by a real local model. The host-side
worker loads the pretrained `yolov8s-worldv2.pt` YOLO-World checkpoint through
PyTorch and uses an indoor vocabulary that includes:

```text
bed, sofa, couch, chair, table, dining table, desk, cabinet, shelf,
bookcase, wardrobe, dresser, nightstand, television, toilet, refrigerator,
oven, sink, lamp, door, window, floor, wall, ceiling
```

The worker receives only the bounded in-memory RGB sweep. YOLO-World supplies
the detected furniture and architectural items. OpenCV analyzes the same
frames for visible structural lines and returns the relative room polygon and
wall segments. No example objects, placeholder room rectangles, or synthetic
openings are added to a result.

## Runtime configuration

The checked-in configuration is
`one/geometry_service/model_config.yolo-world.json`. The model checkpoint is
kept outside Git. A local worker must be started with:

```bash
ONE_GEOMETRY_MODE=model
ONE_GEOMETRY_MODEL_PATH=/absolute/path/to/yolov8s-worldv2.pt
ONE_GEOMETRY_MODEL_CONFIG=/absolute/path/to/one/geometry_service/model_config.yolo-world.json
ONE_GEOMETRY_DEVICE=auto
ONE_GEOMETRY_ALLOW_CPU=false
```

On Apple Silicon, `auto` selects the MPS accelerator. The service reports
`mode: "model"`, `runtime.framework: "pytorch-ultralytics"`, the active device,
and the configured real `model_version` from `GET /health`. A missing weight,
dependency, accelerator, or valid structural result is an unavailable or
rescan-required state. It is never converted into a successful placeholder
map.

The Docker API calls the host worker through
`ONE_GEOMETRY_SERVICE_URL=http://host.docker.internal:8090`; the phone does not
connect to the model process directly. Raw camera frames are discarded after
inference.

## Map output

Each ready camera map carries the model version and real detections in
normalized `0..1` image coordinates:

- `furniture`: labeled objects with detected center, box size, and confidence;
- `openings`: detected doors and windows represented as normalized segments;
- `polygons` and `walls`: structural boundaries estimated from the sweep;
- `metrics` and `diagnostics`: confidence, line-fit error, detection counts,
  model backend, device, and processing method.

These coordinates are relative, not meters. The caregiver can select two points
on the map and enter a known wall, doorway, or object length to store a
reference scale. Native RoomPlan/LiDAR remains the metric 3D path.

## Verification

Before treating the worker as ready, check that `/health` returns `200` and
that the JSON does not report a fixture mode or a placeholder model version.
Then run a fresh sweep. Existing revisions generated by the removed fixture
are retained for audit/history but are not evidence of a real-model result;
the current map should be replaced only by a new successful sweep.
